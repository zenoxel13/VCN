# Метрики моделей прогнозу H / D / A

Розбиття за часом: train < 2022-07-01 ≤ val < 2023-07-01 ≤ test.

**Набори ознак клубів:** `no_odds` — суворий, без жодної ринкової інформації (без f_odds_ і f_hodds_); `hist_odds` — без коефіцієнтів ЦЬОГО матчу, але з історією ринкової оцінки команд у попередніх матчах (f_hodds_); `with_odds` — усе, включно з коефіцієнтами матчу.

**Схема.** Кандидати (логрегресія `logreg_*`, LightGBM `lgbm_*`, ансамбль `ens_*` — зважене середнє LightGBM + логрегресії, для with_odds ще й ринку; ваги — сітка з кроком 0.1) навчаються лише на train. LightGBM: випадковий пошук (20 спроб) на найсвіжіших 30% train з lr 0.1 — один раз на трек (на наборі hist_odds), конфігурація перевикористовується для всіх наборів; далі на всьому train порівнюються звичайне навчання і старт від сильного прогнозу (init_score = log ймовірностей ринку для with_odds або Elo-логрегресії). Ваги свіжості (півперіод 5/8 років) і відкидання ознак з малим gain пробували — на val приросту не дали, тому вимкнені. Логрегресія отримує лог-ймовірності стартового прогнозу як ознаки. Серед калібраторів є температура, що стискає крайні ймовірності. Validation поділено за часом навпіл: 1-ша половина — early stopping LightGBM і калібратор, 2-га — вибір моделі (щоб LightGBM не мав переваги від підгонки під той самий val). Фінальна модель (★ `final_*`) — кандидат із найменшим log-loss на 2-й половині val, ДОНАВЧЕНИЙ на train+val (LightGBM: best_iter × 1.1 дерев). У рядку `final_*` val-метрики — від версії, навченої лише на train (чесна val-оцінка), test-метрики — від донавченої моделі, яку зберігає `models/*.joblib`. Рядки `*_iso` / `*_platt` — обраний кандидат з ізотонічним / Platt-калібруванням, навченим на val (їхні val-метрики оптимістичні; дивитися на test). Калібратор для фінальної моделі обирається так само: навчання на 1-й половині val, оцінка на 2-й. Val-метрики все одно трохи оптимістичні, тож чесне порівняння — лише test.

## Висновки

**Набори ознак клубів.** Фінальна модель без коефіцієнтів (суворий): log-loss 1.0148, accuracy 0.491. Фінальна модель з історією коефіцієнтів: log-loss 1.0093, accuracy 0.497. Фінальна модель з коефіцієнтами матчу: log-loss 1.0022, accuracy 0.503. Набір hist_odds чесно придатний для прогнозу ДО появи коефіцієнтів: коефіцієнтів цього матчу в ньому немає, є лише ринкова оцінка команд у їхніх попередніх матчах (f_hodds_*). Ринок (коефіцієнти БК напряму): log-loss 1.0029, accuracy 0.502. Коефіцієнти концентрують інформацію, якої немає в публічній статистиці (склади, травми, мотивація), тому модель без них очікувано трохи гірша; модель з ними здебільшого відтворює ринок.

**Чому нічиї майже не прогнозуються.** Нічия майже ніколи не є найімовірнішим результатом: навіть для рівних суперників P(нічия) зазвичай ≈ 0.27–0.32, а P(H) або P(A) вища. Argmax тому обирає H/A, і це оптимально для accuracy; ймовірність нічиєї при цьому відкалібрована, що видно на log-loss/RPS. Клуби/no_odds: модель прогнозує нічию в 0.5% матчів (фактично нічиїх 26.4%; макс. P(нічия) = 0.42); Клуби/hist_odds: модель прогнозує нічию в 0.4% матчів (фактично нічиїх 26.4%; макс. P(нічия) = 0.40); Клуби/with_odds: модель прогнозує нічию в 0.6% матчів (фактично нічиїх 26.4%; макс. P(нічия) = 0.46); Збірні/no_odds: модель прогнозує нічию в 1.7% матчів (фактично нічиїх 23.0%; макс. P(нічия) = 0.42).

**Тест на витік.** Пройдено. Клуби: max accuracy 0.503; Збірні: max accuracy 0.617 (baseline_elo 0.603, макс. приріст +1.4 п.п.). Правило: клуби — test accuracy ≤ 60%; збірні — не більше ніж на 5 п.п. краще за baseline_elo і ≤ 70% (сам baseline_elo — лише ≤ 70%). Для збірних абсолютний поріг 60% не працює: майже половина матчів test — явно нерівні пари (|різниця Elo| > 200, напр. Німеччина — Сан-Марино), і просте правило «перемагає вищий Elo» саме дає ~60% accuracy. Справжній витік дав би стрибок на 10–20 п.п. над Elo, чесні ознаки — 1–2 п.п. Elo збірних перевірено як передматчевий: кореляція результату зі зміною Elo до матчу ≈ 0.03, після матчу ≈ 0.77.
